Local JSON before writeback

Every node, by layer. Layer 0 is what we were given; layer 3 is what we are willing to say. RECOMPUTED means the bytes are in the store and were re-hashed. COMMITTED means we hold a digest captured at origin and nothing more — honest for a 13 MB parquet on someone else's bucket.

Full SQL over the ledger. Nothing is hidden and nothing is rate-limited, because the database is already on your machine. Changes you make here affect only this browser tab — and the PROVE tab will notice them.

This does not trust the stored root. It reads the record bytes of all 62 nodes, hashes each into an RFC 6962 leaf (sha256(0x00 ‖ record)), rebuilds the tree (sha256(0x01 ‖ left ‖ right), split at the largest power of two below n), and only then compares. If the comparison fails, something in the chain is wrong and you should not believe the rest of this page.

What this is

A projection of fcg/store/, which is the actual ledger. This database is regenerated from the store and never edited by hand. If the two ever disagree, the store is right and this file is stale.

The database is downstream of the Merkle root and never upstream of it. Hashing the .db into the graph would be circular — the digest would change the graph, which would change the .db, which would change the digest. So the root goes into the database, and the database's own digest is published beside it in publish_manifest.json.
